# Browser-local learner save contract

`schemaVersion` is independent of bundled content's `formatVersion` and `contentVersion`. The save is one JSON object, not a serialized practice session. Decoding and migration are pure in-memory operations; they do not read or write storage. Callers supply a new `snapshotId` on version-0 migration (or use the codec's generated identity); a later explicit save must compare against the original stored raw text before replacing it. A failed migration leaves that text untouched.

## Version 1 (current)

The envelope has `schemaVersion: 1`, `savedAtEpochMs`, `snapshotId`, `revision`, `preferences`, `lessonProgress`, `practiceProgress`, and `reviewItems`. Encoding emits every field, including default and null fields. Preferences contain `colorMode` (`system`/`light`/`dark`), `showReadings`, `showTranslation`, and `showRomaji`. Lesson records contain `lessonId`, `contentVersion`, `updatedAtEpochMs`, `stage` (`situation`, `dialogue`, `understanding`, `guidedPractice`, `rolePlay`, `summary`), nullable `checkpointId`, and nullable `completedAtEpochMs`. Review records contain `itemId`, `documentId`, `outcome` (`again`/`hard`/`good`), `lastReviewedAtEpochMs`, nullable `dueAtEpochMs`, `intervalMs`, `step`, `repetitions`, `lapses`, and `lastActionToken`.

Practice records contain one latest checkpoint per `setId`: `contentVersion`, `updatedAtEpochMs`, `runToken`, `lastTransitionToken`, ordered `exerciseIds`, ordered compact `outcomes`, `frontier`, `view`, and nullable `lastCompletedAtEpochMs`. There is no saved answer, response text, authored content, or history. See `SaveModels.kt` and `SaveValidation.kt` for exact wire names, enumerations, defaults, bounds, and frontier consistency rules. Unknown but syntactically valid content IDs are retained without catalog lookup.

## Version 0 (compatibility fixture)

Version 0 is a **new compatibility/test fixture introduced with F03**, not a learner-save format previously shipped by this repository. Its object must contain exactly the top-level fields `schemaVersion: 0`, `savedAtEpochMs`, `preferences`, `lessonProgress`, and `reviewItems`; no version-1-only fields are accepted. Its `preferences` must contain `colorMode`; the three study-support booleans may be absent and then default to `showReadings: true`, `showTranslation: true`, `showRomaji: false`. Present booleans are preserved. Lesson and review records use the version-1 wire shapes: the nullable lesson checkpoint/completion and review scheduling fields may be absent (default null); all other record fields are required. Arrays themselves and the preferences object are required, even when empty. No additional fields are accepted at any level.

Migration first validates the precursor's wire types, records, timestamps, IDs and limits, then supplies only those documented absent defaults. It preserves existing records and timestamps, creates an empty `practiceProgress`, sets `revision` to zero, injects a new bounded `snapshotId`, and validates and byte-checks the resulting version-1 envelope. It returns `migratedFrom: 0`; re-encoding the migrated snapshot produces version 1. Invalid input, an invalid generated identity, or a throwing identity supplier returns `Protected(INVALID_SNAPSHOT)` rather than partially migrating; the original raw text remains available for recovery.

Missing, malformed, negative, fractional, or unsupported versions (including future versions) are protected, never guessed as version 0 or downgraded. Duplicate keys, unknown fields, bad types/enums, impossible records, oversized input, and excessive JSON depth are also protected. Protected text is not truncated, rewritten, or exposed as a usable save by the codec.
