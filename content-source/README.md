# Content authoring (contract foundation)

This directory holds authoring material, not a runtime loader or learner saves. The canonical public JSON tree will be added under `site/src/jsMain/resources/public/content/` in later F01 steps. The current contracts are in `shared/src/commonMain/kotlin/com/github/nanaki_93/content/ContentModels.kt`. Exercise variants, graph data, strict codec, filesystem validation, and promotion are subsequent steps; do not treat an unvalidated document as publishable.

## Identity and versions

Wire names are explicitly annotated with `@SerialName`; JSON keys use camelCase. `formatVersion` is required and currently exactly `1`; `contentVersion` is a required positive integer. Catalog and documents must share both versions (cross-document validation will check that). These are **content** versions, not the future learner save `schemaVersion` (F03). Difficulty is advisory, never a proficiency certification or unlock rule.

Stable IDs match `[A-Za-z0-9][A-Za-z0-9_-]*` (ASCII only; existing hyphenated UUIDs fit). Do not derive IDs from a title, translation, list position, or hash. Keep IDs on reordering, copy corrections, or a `contentVersion` increase; give a materially new learning objective a new ID. Catalog topic IDs are unique among topics, document IDs among entries, and audio IDs among assets. Phrase, exercise, and review-item IDs each have their own **catalog-wide** namespace across all documents; speaker, dialogue-turn, choice-option, and graph-node IDs are unique within their owning document. Local duplicate checks are in the models where available; cross-document uniqueness and reference resolution belong to the later validator. IDs in references retain their owning context: catalog entries identify the document, and `targetKind` plus `targetId` identifies the local review target. Referenced lesson prerequisites are lesson IDs, not display labels.

Required properties have no default empty-string values. Optional lists and audio references may be omitted where declared. Catalog entries specify `kind` (`lesson` or `practice`), `topicId`, and a relative `path`; path safety and existence will be enforced by the validator. A dialogue declares speakers and ordered turns; turns refer to speaker IDs. Phrases can link to a source turn and optionally to a catalog audio ID. No recording is required for text-only content. `JapaneseText` requires a surface, authored reading, and **exactly one** translation or isolated-kana sound/usage gloss. A gloss is reserved for a single precomposed hiragana or katakana sign (not a kana-only word, contracted pair, or standalone length mark); use a translation for those other surfaces. Its optional segments must concatenate exactly to the surface; any segment containing kanji/iteration marks, including supplementary-plane CJK ideographs, needs an authored reading. Non-kanji punctuation or mixed code segments can omit a segment reading. No pronunciation or answer variants are inferred from romanization. Register and context notes are optional; phrases also require usage and register. Role-play criteria are self-assessment prompts, not grading rules. Review metadata records reviewer type, date, review-note reference, provenance, rights status and basis; merely constructing metadata does not constitute rights clearance. Later validation gates reviewed status, publishable rights, and evidence.

In `shared` the models currently reject local invalid values in constructors and on deserialization; a strict document decoder and cross-document CLI checks arrive in later F01 steps. For the current contract compilation check run `./gradlew :shared:allMetadataJar :shared:compileKotlinJvm && git diff --check` from the repository root. Do not promote legacy drafts or F00 mock copy without fresh review.
